# --- real hardware -----------------------------------------------------------
# ONLY used by hardware/real_arm.py under `--mode real`; harmless in sim.
#
# PINNED DELIBERATELY. UFACTORY renamed the linear-rail and force/torque APIs
# between 1.14.x and 1.18.x with no backward-compatible aliases:
#
#     set_linear_track_pos  (<=1.14.x)  ->  set_linear_motor_pos  (>=1.18)
#     ft_sensor_enable      (<=1.14.x)  ->  set_ft_sensor_enable  (>=1.18)
#
# With no pin, a fresh `pip install xarm-python-sdk` resolved to whatever was
# current, and real_arm.py's exception handler turned the resulting
# AttributeError into a *success* return — the rail silently never moved.
# real_arm.py now capability-probes at construction, so either version works,
# but the pin makes which one you get a decision rather than an accident.
#
# 1.18.4 chosen over 1.14.7 because it adds:
#   - get_gripper_status          better grasp verification than position alone
#   - set_gripper_g2_position     required if the fitted gripper is a G2
#   - set_bio_gripper_force       required for force-limited 96-well plate grips
# Confirm controller firmware supports it (`arm.get_version()`); some methods
# carry firmware minimums. If firmware is too old, drop to 1.14.7 — the probe
# handles it — and record why here.
#
# NOTE: ufactory_vision pins 1.14.7 and lives in its own conda env. Do not
# merge these environments (it also pins torch 2.4.1 against ot2vision's 2.13).
xarm-python-sdk==1.18.4
